# Running the mock

The live-loop mechanics for Steps 2, 4, and 5.

## Question count by duration

A real interview does not cram. Match the count so the practice teaches the right pace.

| Round length | Substantive questions | Notes |
| --- | --- | --- |
| 30 min (recruiter / peer) | 4–5 | Plus 3–5 min at the end for their questions. |
| 45 min (hiring manager / panel) | 5–6 | One of these is a longer resume deep-dive. |
| 60 min (HM / behavioral) | 6–8 | Room for one hard follow-up chain. |
| 45–90 min (technical / case) | 1–2 prompts | Each is an extended back-and-forth, not a single answer. |

Always reserve the last segment for the user asking *you* (as interviewer) questions, and assess those.

If the user wants a short session, don't just truncate — tell them which segment you're running (e.g. "we'll do the hiring-manager core, 5 questions, ~20 minutes") so the pacing still means something.

## Interviewer personas and register

Adopt the persona from Step 2. Each asks differently:

- **Recruiter** — warm, brisk, surface-level, moves fast between topics. "Great, and what are you looking for comp-wise?" Doesn't dig; takes notes; keeps time.
- **Hiring manager** — the most engaged. Follows up, pushes on specifics, visibly evaluating "can you do my job." "Okay, but what did *you* decide there?"
- **Skip-level / exec / founder** — fewer questions, bigger, more silence after your answer. Testing ceiling and judgment. "Why is that the right bet?"
- **Peer / panel** — collegial but evaluating "would I want you here." More scenario-based, more about how you work than what you achieved.
- **Technical interviewer** — problem-focused, interjects with constraints, watches how you think under a live load.

Match phrasing and depth to the persona. A founder does not say "tell me about a time you demonstrated cross-functional leadership" — they say "when did you last change someone's mind about something that mattered."

## Staying in character

- Ask one question. Stop. Wait for the full answer.
- No "the next question will be about X" previews. No reading out the agenda.
- Between questions, a short interviewer-ish bridge is fine ("Makes sense. Different topic —").
- The **feedback** breaks character — that's fine and expected. Give it clearly as the coach, then return to character for the next question. A simple marker helps: feedback in a distinct block, then "Back in the room:" before the next question.
- If the user asks mid-mock "how am I doing," give them one honest line and keep going. The debrief is where the full picture goes.

## Pacing the feedback

- Strong answer: one or two lines, then next question. Don't pad.
- Weak answer: the scorecard line + the one fix + (if warranted) the follow-up probe. Still tight — a few lines.
- Never stop the simulation to teach a framework. If they clearly don't know STAR, note it once in feedback and save the teaching for the debrief.
- The follow-up probe is the highest-value moment — a prepared answer survives the first question and falls apart on "and what would you have done differently." Use it whenever a real interviewer would.

## Redo / skip

Tell the user up front they can say:

- **"redo"** — re-answer the same question. Compare the two in one line.
- **"skip"** — move on; note it in the debrief as not practiced.
- **"harder" / "easier"** — adjust the remaining set.

## If the JD is thin or missing

If the user can't provide a real JD (only a title, or a vague blurb), say the mock will be less predictive, then build the set from the title + seniority + company type and lean on general per-round questions. Flag in the debrief which parts couldn't be tailored.
